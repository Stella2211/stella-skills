# stella-skills

Codex の拡張可能なプラグインマーケットプレイスです。遅延したメッセージ送信や長時間ジョブを扱う `codex-sidekick` と、日本語ドキュメントを作成・更新する `docs-writer` を収録しています。

## 概要

| 項目 | 内容 |
| --- | --- |
| マーケットプレイス名 | `stella-skills` |
| 現在のプラグイン | `codex-sidekick`、`docs-writer` |
| スキルの目的 | 長時間ジョブの運用と、根拠に基づく日本語ドキュメント作成 |
| 実現すること | queue機能とOSのタイマー機能によるジョブ運用、コードの現状に合わせた文書作成とtextlintによる確認 |
| 対応 OS | macOS、Linux、Windows（機能と検証範囲は OS ごとに異なります） |

`codex-sidekick` は、queue機能とOSのタイマー機能を組み合わせて、Claude Codeのmonitorのような機能を実現します。これは利用イメージを伝えるためのたとえです。Claude Code との互換性や同一実装を意味しません。収録スキルは非公式の個人用スキルで、OpenAI の公式機能ではありません。

## GitHubからインストールする

```sh
codex plugin marketplace add Stella2211/stella-skills
codex plugin add codex-sidekick@stella-skills
codex plugin add docs-writer@stella-skills
```

必要なプラグインを選んで追加します。インストール後、新しい会話のスキル一覧で追加したスキルを確認してください。プラグイン導入時はスキル名に名前空間が付く場合があるため、表示される名前を使用してください。

## codex-sidekick の使い方

自然言語で用途を伝えて依頼します。

```text
30分後に、このスレッドへ現在時刻を確認するメッセージを送ってください。
```

```text
この長時間ジョブを Codex アプリを閉じても続けられるように設定し、1時間ごとを基本に進捗を報告してください。最長でも通常は4時間を超えない間隔にし、検証結果が出たら途中でも報告してください。
```

```text
この処理を OS のジョブとして登録してください。登録済み、実行中、完了をジョブ ID・プロセス状態・ログ・終了ステータス・生成物で確認し、停止方法も残してください。
```

### 遅延メッセージ

`codex queue` と各 OS のスケジューラを組み合わせます。スケジューラへの登録、queue の受付、実際のスレッドでの実行を別々に確認します。登録できたことだけでは、メッセージが届いたことを意味しません。

### 長時間ジョブ

計算本体と進捗通知を分離します。queue の失敗、通知のタイムアウト、Codex アプリの終了が起きても、計算本体を止めたり失敗扱いにしたりしないようにします。進捗はローカルに保存し、必要なら後から確認できるようにします。通常の進捗報告は1時間ごとを基本にし、実用上はおおむね4時間を最長の定期間隔とします。処理の性質に合わない場合は、10%ごと、検証完了時、フェーズ完了時などのマイルストーンに切り替えます。

Codex アプリを閉じた状態や、対象スレッドが読み込まれていない状態で、即座に応答が返るとは限りません。スリープ、ログアウト、シャットダウン、再起動、ユーザーサービスの状態も実行結果に影響します。OS ジョブの実行と、Codex がメッセージを消費して応答することは別々に確認してください。

## docs-writer の使い方

読者、対象範囲、前提を指定して依頼します。スキルは現在のコードと設定を確認し、読者に必要な情報だけで日本語ドキュメントを作成・更新します。文章を書き終えたら、対象ファイルを明示して textlint を実行し、指摘を確認して修正します。

```text
この機能の利用者向けガイドを、現在のコードに合わせて日本語で作成してください。対象は初回設定から基本操作までです。最後にtextlintで確認してください。
```

検査には Bun と Node.js が必要です。初回に専用キャッシュへ依存を取得し、対象プロジェクトに依存や設定を追加せずに実行します。macOS で実行を検証しています。

lint の実行契約とキャッシュの扱いは [`docs-writer` の参照資料](plugins/docs-writer/skills/docs-writer/references/textlint.md) に記載しています。

## codex-sidekick の対応状況

- macOS: `launchd` の登録・状態確認・解除と、ツール呼び出し終了後も続く短時間の処理を検証済みです。利用者から遅延通知・短時間の長時間ジョブ動作テストの成功報告があります。アプリ終了を含む条件別の再現試験や、1週間の連続実行は未検証です。
- Linux: `systemd --user` を使う手順を収録しています。手順はドキュメントに基づくもので、macOS の作成環境では実機検証していません。
- Windows: タスク スケジューラを使う手順を収録しています。手順はドキュメントに基づくもので、macOS の作成環境では実機検証していません。

対応状況は、特定の OS、Codex CLI、ユーザーセッション、電源状態の組み合わせで変わります。利用を始める前に、実際の実行ファイル、`CODEX_HOME`、作業ディレクトリ、対象スレッド ID、ログの保存先を確認してください。
