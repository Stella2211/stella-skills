# Long Task Execution

## このスキルの目的

大きく不安定さを伴うタスク（機械学習など）を、途中で目的を見失うことなく効率的に遂行するためのスキル。大きくても目的が明確な作業（リファクタリングなど）は対象外。

## 常に意識すること

ユーザーから与えられた最終目標を達成するために必要な作業だけを行うこと。「テストのためのテスト」や、最終目標と関係のない作業は行わない。

## 最初に決めること

ユーザーからタスクを与えられたら、進捗管理シートを作成する。この際、シートには次の内容を含める：

- 最終目標
- それに対する現在の進捗(作業IDを用いた1文)
- 作業一覧表
- 最終更新日時

作業一覧表には次の内容を含める：

- 作業ID
- 作業を行う条件(作業ID〇〇の失敗時・成功時など)
- 作業の目的
- それが最終目標とどのように関わるのか
- 完了条件
- 想定作業時間
- 最大作業時間（これを超過したら超過理由と今後の行動案をユーザーに報告する）

### 作業実施の判断基準

作業を行うか否かは、その作業が次の基準に該当する項目があるかで決定する：

- 最終目標へ直接寄与する
- 次の重要判断を左右する
- 重大な失敗、受入条件違反、不可逆な誤操作を防ぐ

該当する項目がない場合、原則としてその作業は行わない。もしこれらに該当しないが行うべきだと考える作業があるのなら、ユーザーに承認を求める。

### 検証作業について

検証は失敗時の損失に比例させる。１時間未満の比較的コストの低い実験のために、複数エージェントでのクロスレビューや大量のテストの作成を行わない。高コスト実行(機械学習の場合は本学習開始など)の前には入力、設定、更新数、時間上限、失敗時停止を確認する。

## 作業中に考えること

進捗管理シートが完成し、作業に着手可能な状態になったら、AGENTS.mdの記載にあるように積極的にサブエージェントを使いながら作業を遂行する。あなたは長期的視野を持ったリーダーとして、エージェントの指示の際は常に「それが最終目標の達成にどの程度寄与するか」を考え、必要な指示を行う。 **目先の作業に囚われ、全体を見失ってはならない**

作業中、進捗管理シートにないが行うべき追加作業が発生した際は、前述の「作業実施の判断基準」に照らし合わせて必要性を判断し、本当に必要な場合のみ実行する。この際、進捗管理シートにも追記すること。

## 意識すること

- **オーバーエンジニアリングを行わない：** 常に最小実装を心がける。コードが複雑になるにつれてバグが発生する可能性が高まり、テストも増える。常にシンプルで最小限の作業を心がける
- **巨人の肩に乗る：** 先行研究があったり、やりたい実装にふさわしいライブラリがある場合はそれを使用する。車輪の再発明を行わない。
- **ハッシュ計算には時間がかかる：** ファイルのダウンロード直後のハッシュ検査など、必要な場面でのみ行う。スクリプトにハッシュ計算を組み込み、毎実行時に整合性を確認する必要は基本的にない。
- **KISS,YAGNI,DRY原則を守る：** ソフトウェア開発において重要とされている原則には、そう言われるだけの価値がある。これらを遵守し、クリーンなコードを書くことこそが成功への近道である。
- **上記の原則をドキュメント管理にも適用する：** 特にDRY原則は重要。同じような文章を何度も書かない。必要な情報を必要なファイルに記載し、他のファイルから参照したいときもコピペしないで当該ファイルへ誘導する。
- **時間効率を意識する：** 時間は有限である。並行して進められる作業は並行して進めるなど、時間効率を意識して作業する。
