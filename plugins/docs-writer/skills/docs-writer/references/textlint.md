# textlintの実行方法

このスキルのlintは、明示したMarkdown・テキストファイルの文章表現を検査する。
内容の事実性、実験の妥当性、現在状態の正しさ、根拠の十分さは別に確認する。

## 実行

```sh
bun <absolute-skill-path>/scripts/lint-docs.ts <file> [files...]
```

`<absolute-skill-path>`はインストール先の実際の絶対パスに置き換える。

```sh
bun /path/to/docs-writer/scripts/lint-docs.ts README.md docs/setup.md
```

- 対象ファイルを1つ以上、明示的に渡す。glob展開は行わない。
- 相対パスは、コマンドを呼び出したカレントディレクトリから解決する。
- 変更した文書をまとめて検査する。進捗の小更新ごとに全ドキュメントを検査する必要はない。
- コマンドの実行担当は、適用されるAGENTS.mdの委任方針に従う。

## 実行環境とキャッシュ

- 既存の同梱説明での検証環境はBun 1.3.14。Node.jsは20.18.0以降が必要。
- 初回はネットワーク接続を使い、固定されたpackageとlockfileから専用キャッシュへ依存関係をインストールする。
- キャッシュの既定値は`~/.cache/stella-skills/docs-writer`。
- `DOCS_WRITER_CACHE_DIR`に絶対パスを指定すると変更できる。
- キャッシュは次回以降再利用する。通常の文書更新で削除・再構築しない。
- package、lockfile、設定、Bunのバージョン等が変わると、対応する別のキャッシュが作られる。
- package、設定、キャッシュを対象プロジェクトやインストール済みプラグインへ書き込まない。

キャッシュへ書き込めない場合は、プロジェクトとスキルの外にある書き込み可能なディレクトリを指定する。
明示的に破損したキャッシュがエラーで特定された場合は、そのディレクトリだけを対象に復旧する。

## 検査内容

- 同梱ルールだけで検査する。対象プロジェクトのtextlint設定や除外設定は読み込まない。
- 対象ファイル自体を自動編集しない。
- 禁止表現の検査では引用とコードを除外する。
- 正規表現では`強み`や`強いて`も検出対象になる。
- `正本`は`SSoT`へ置き換える。
- `上流`は、別リポジトリを指す場合は具体的なリポジトリ名へ、それ以外は`アップストリーム`へ置き換える。

指摘を消すために事実、重要な制約、適用条件を削除しない。
必要な内容を保ったまま表現を修正する。

## 終了コードと報告

| 終了コード | 意味 |
|---|---|
| `0` | lint指摘なし |
| `1` | lint指摘あり |
| `2` | 実行エラー |

指摘があれば内容を確認して修正し、対象ファイルを再検査する。
依存関係の取得、コマンド実行、結果確認ができない場合は、その事実を報告し、lint済みとは書かない。

実行エラーを文書内容の誤りと混同しない。
軽微な環境問題は担当範囲内で対処するが、lintのためだけに依頼外の大規模な環境改修を始めない。
未実行・未解決の検査は明記し、他の独立した作業は進める。

lintの成功は文章表現の検査結果であり、実験や学習、プログラム全体の成功を意味しない。
