# textlint の実行契約

スキルの lint は、次の形式で実行する。

```sh
bun <absolute-skill-path>/scripts/lint-docs.ts <file> [files...]
```

たとえば対象プロジェクトのルートで次のように実行する。スキルのパスはインストール先に置き換える。

```sh
bun /path/to/docs-writer/scripts/lint-docs.ts README.md docs/setup.md
```

- `scripts/lint-docs.ts` は対象ファイルを1つ以上受け取る。glob 展開は行わない。
- 相対入力は、コマンドを呼び出したカレントディレクトリから解決する。
- Bun（1.3.14 で検証）と Node.js 20.18.0 以降が必要。初回はネットワーク接続を使って、固定されたパッケージと lockfile をキャッシュへインストールする。
- キャッシュの既定値は `~/.cache/stella-skills/docs-writer`。`DOCS_WRITER_CACHE_DIR` に絶対パスを指定すると変更できる。キャッシュは次回以降再利用する。
- パッケージ、設定、キャッシュは対象プロジェクトやインストール済みプラグインへ書き込まない。
- このコマンドは同梱ルールだけで検査する。対象プロジェクトの textlint 設定や除外設定は読み込まない。ファイル自体も変更しない。
- 禁止表現の検査では引用（`>`）とコードを除外する。正規表現は`強み``強いて`も検出対象とする。
- 終了コード `0` は指摘なし、`1` は lint 指摘、`2` は実行エラーを示す。

指摘があれば内容を確認して修正し、lint を再実行する。依存関係の取得や実行ができない環境では、その事実を報告し、成功したとは書かない。

キャッシュに書き込めない場合は、プロジェクト外の書き込み可能なディレクトリを `DOCS_WRITER_CACHE_DIR` に指定する。依存・設定・Bun のバージョンが変わると別のキャッシュを作成する。破損したキャッシュのパスがエラーに表示された場合は、そのディレクトリを削除して再実行する。
