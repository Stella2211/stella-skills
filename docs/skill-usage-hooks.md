# 使用したスキルだけをCompaction後に復元する

`docs-writer`と`long-task-execution`は、自分のスキルを採用したスレッドにだけ本文を復元するHookを同梱しています。インストールしているだけのスキルは投入しません。登録はエージェントが一度行い、その後はローカルの小さなマーカーで判定します。

## 導入

マーケットプレイスから両プラグインを更新・再インストールし、manifestのversionが`0.1.1`以降になったことを確認してください。新しいHook定義は各環境のCodexで`/hooks`から確認し、内容を確認して信頼を登録します。既存のユーザー設定に同じスキルを無条件再投入するHookがある場合は、その該当設定を外して二重投入を避けます。他のHookは残してください。

Hookと登録コマンドには`uv`と、uvからオフラインで利用できるPython 3.10以降が必要です。実行は標準ライブラリだけを使い、Hook自体は依存取得やネットワークアクセスを行いません。Pythonをまだ用意していない環境では、通常の環境準備として先に用意してください。

親が自分の登録を行えるよう、`my-codex-settings`のAGENTS.mdにあるスキル使用登録の直接操作例外も適用します。この例外はプラグインの任意スクリプトを自由に実行する許可ではありません。

## スキルを採用したときの登録

各エージェントは、スキルを現在の作業に適用すると決めたときだけ、次を一度実行します。`<absolute-skill-path>`は現在のスキル一覧にある、SKILL.mdを含むディレクトリへ置き換えてください。インストール版の番号やユーザー名を固定する必要はありません。

```sh
uv run --offline --no-project python "<absolute-skill-path>/../../hooks/skill-usage.py" activate
```

登録対象は実行環境の`CODEX_THREAD_ID`です。親の登録を子へ委任したり、子のIDを親のIDへ書き換えたりしません。スキル本文の閲覧・レビュー・編集だけでは登録しません。登録済みの再実行は空のマーカーを増やしません。

```sh
# 自分のスレッドについて状態確認
uv run --offline --no-project python "<absolute-skill-path>/../../hooks/skill-usage.py" status

# 同じ会話を別用途へ切り替えた場合などに解除
uv run --offline --no-project python "<absolute-skill-path>/../../hooks/skill-usage.py" deactivate
```

外部ターミナル等で`CODEX_THREAD_ID`がない場合は、登録を失敗として報告します。別スレッドのIDを推測・流用せず、現在のエージェントのネイティブ実行環境を使います。登録ができなくても、本来の作業を停止せず、必要なスキルは通常の方法で読みます。

## 復元と状態の寿命

| 場面 | 挙動 |
|---|---|
| 親のCompaction | 親の登録があるプラグインだけが、自分のSKILL.md全文を返す |
| 未登録のプラグイン | SKILL.mdを読まず、標準出力なしで終了する |
| 子だけでの使用登録 | 子のthread IDに保存し、親の復元対象へ合流しない |
| 通常の再開・アプリ終了 | 登録を維持する。終了時に自動削除しない |
| 新しいスレッド・fork | 新IDなので未登録。必要なスキルをそのスレッドで採用時に登録する |
| `clear` | イベントのsession IDについて、そのプラグインのマーカーだけを削除する |
| 明示的な解除 | 現在のスレッドにある、そのプラグインのマーカーだけを削除する |

この連携は親の`SessionStart`（`source: compact`）を対象にしています。子のCompaction後の発火は保証せず、子自身にも通常の再開手順を残します。`agent_id`付きのイベントは親の登録を変更しません。

保存内容は空のマーカーだけです。既定の場所は`${CODEX_HOME:-~/.codex}/stella-skills/skill-usage/<thread-id>/<plugin-name>.active`です。スキル本文・会話・インストールパス・認証情報は保存しません。明示的な解除以外に古い別スレッドのマーカーを走査・削除する機能はありません。

保存先を変える場合は`STELLA_SKILL_USAGE_DIR`に絶対パスを指定します。**登録コマンドとHookの両方へ同じ値を渡してください。** `PLUGIN_DATA`はHookだけに渡される環境と混同しないため、保存先として自動採用しません。必要な書き込み権限は通常の承認手順で扱い、登録のためにsandbox全体を解除しません。保存先の不一致は`status`が返すmarkerパスで確認できます。

登録はローカル環境ごとです。同じスレッドを別PCへ移して継続する場合は、必要なスキルをその環境で再登録します。プラグイン配布だけで使用履歴が同期されるわけではありません。

## 失敗時と制限

マーカー未登録時には、代わりのスキルや注意文もモデルへ投入しません。登録の初回操作をモデルが忘れた場合は自動復元できないため、各SKILL.mdに採用時の登録指示を置いています。

ファイル欠落、不正なID、読み取り失敗、出力上限超過では、Hookは標準エラーに理由を出し、本文を投入せず終了します。本来の作業を止める出力や全スキル投入への切り替えは行いません。`/hooks`の実行結果を確認し、必要な本文を通常の読み取りで補ってください。

各SKILL.mdは16 KiB、付加文脈全体は20 KiB以内です。Hook設定の`additionalContextLimit: 0`はこの上限と組み合わせ、本文の途中省略を避けます。参照資料は自動投入せず、Skillの適用条件に従って必要な場合だけ読みます。

## 検証

```sh
uv run --no-project python -m unittest discover -s tests -p test_skill_usage_hooks.py -v
```

テストは実ヘルパーを子プロセスで動かし、未使用時の無出力、登録、解除、親子分離、clear、保存先、出力上限、版更新を確認します。uvがある場合は同梱Hookのコマンドも実行します。CIにはLinux・macOS・Windowsの実行を設定しています。テスト結果は該当PRのChecksを参照してください。

これらのテストは、実CodexでのHook信頼登録、実スレッドIDの引き渡し、自動・手動Compactionの発火を代替しません。実機では未使用セッションと使用済みセッションをそれぞれ圧縮し、Hook結果を確認してください。

公式仕様: [Codex Hooks](https://learn.chatgpt.com/docs/hooks)。各プラグインは自分のmanifestと本文だけを読み、他プラグインのキャッシュ探索や巨大なセッションログの解析は行いません。
